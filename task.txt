### Database schema

The database contains the following nine core tables.

### Table 1: `users`

Columns:

- `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
- `full_name VARCHAR(100) NOT NULL`
- `email VARCHAR(255) NOT NULL UNIQUE`
- `password_hash VARCHAR(255) NOT NULL`
- `platform_role VARCHAR(20) NOT NULL DEFAULT 'USER'`
- `is_active BOOLEAN NOT NULL DEFAULT TRUE`
- `created_at TIMESTAMPTZ NOT NULL`
- `updated_at TIMESTAMPTZ NOT NULL`

Allowed `platform_role` values: `USER`, `ADMIN`.

Use BCrypt for passwords. Never store plaintext passwords or return password hashes through API responses.

### Table 2: `projects`

Columns:

- `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
- `name VARCHAR(150) NOT NULL`
- `project_key VARCHAR(10) NOT NULL UNIQUE`
- `description TEXT`
- `status VARCHAR(20) NOT NULL DEFAULT 'ACTIVE'`
- `owner_id UUID NOT NULL REFERENCES users(id)`
- `created_at TIMESTAMPTZ NOT NULL`
- `updated_at TIMESTAMPTZ NOT NULL`

Allowed statuses: `ACTIVE`, `ON_HOLD`, `COMPLETED`, `ARCHIVED`.

Validate project keys and keep them immutable after project creation unless a deliberate, authorized change mechanism is implemented.

### Table 3: `project_members`

Columns:

- `project_id UUID NOT NULL REFERENCES projects(id)`
- `user_id UUID NOT NULL REFERENCES users(id)`
- `role VARCHAR(20) NOT NULL`
- `joined_at TIMESTAMPTZ NOT NULL`
- Composite primary key: `(project_id, user_id)`

Allowed roles: `OWNER`, `MANAGER`, `MEMBER`, `VIEWER`.

### Table 4: `issues`

Columns:

- `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
- `project_id UUID NOT NULL REFERENCES projects(id)`
- `issue_number INTEGER NOT NULL`
- `title VARCHAR(200) NOT NULL`
- `description TEXT`
- `issue_type VARCHAR(20) NOT NULL`
- `status VARCHAR(20) NOT NULL DEFAULT 'TODO'`
- `priority VARCHAR(20) NOT NULL DEFAULT 'MEDIUM'`
- `reporter_id UUID NOT NULL REFERENCES users(id)`
- `due_date DATE`
- `estimated_hours NUMERIC(8,2)`
- `created_at TIMESTAMPTZ NOT NULL`
- `updated_at TIMESTAMPTZ NOT NULL`

Allowed issue types: `TASK`, `BUG`, `STORY`, `EPIC`.

Allowed statuses: `TODO`, `IN_PROGRESS`, `IN_REVIEW`, `DONE`, `CANCELLED`.

Allowed priorities: `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`.

Constraints:

- `UNIQUE(project_id, issue_number)`
- `UNIQUE(id, project_id)` to support the composite foreign key in `issue_labels`
- Issue numbers must be positive.
- Estimated hours must be nonnegative.

Generate issue numbers safely when multiple requests create issues concurrently. Do not use `MAX(issue_number) + 1` without transaction-safe locking or another concurrency-safe mechanism.

### Table 5: `issue_comments`

Columns:

- `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
- `issue_id UUID NOT NULL REFERENCES issues(id)`
- `author_id UUID NOT NULL REFERENCES users(id)`
- `content TEXT NOT NULL`
- `created_at TIMESTAMPTZ NOT NULL`
- `updated_at TIMESTAMPTZ NOT NULL`

Comments must not be empty or whitespace-only.

### Table 6: `issue_assignees`

Columns:

- `issue_id UUID NOT NULL REFERENCES issues(id)`
- `user_id UUID NOT NULL REFERENCES users(id)`
- `assigned_at TIMESTAMPTZ NOT NULL`
- Composite primary key: `(issue_id, user_id)`

Support multiple assignees per issue.

### Table 7: `labels`

Columns:

- `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
- `project_id UUID NOT NULL REFERENCES projects(id)`
- `name VARCHAR(50) NOT NULL`
- `color VARCHAR(7) NOT NULL DEFAULT '#808080'`
- `created_at TIMESTAMPTZ NOT NULL`
- `UNIQUE(project_id, name)`
- `UNIQUE(id, project_id)`

Validate hexadecimal color values.

### Table 8: `issue_labels`

Columns:

- `issue_id UUID NOT NULL`
- `label_id UUID NOT NULL`
- `project_id UUID NOT NULL`
- Composite primary key: `(issue_id, label_id)`

Composite foreign keys:

- `(issue_id, project_id)` references `issues(id, project_id) ON DELETE CASCADE`
- `(label_id, project_id)` references `labels(id, project_id) ON DELETE CASCADE`

Preserve these constraints so a label cannot be assigned to an issue from a different project.

### Table 9: `issue_history`

Columns:

- `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
- `issue_id UUID NOT NULL REFERENCES issues(id)`
- `changed_by UUID REFERENCES users(id) ON DELETE SET NULL`
- `field_name VARCHAR(50) NOT NULL`
- `old_value TEXT`
- `new_value TEXT`
- `changed_at TIMESTAMPTZ NOT NULL`

Record meaningful issue changes, including status, priority, assignees and other supported fields. Capture the authenticated user as the actor. History should not be editable through ordinary client-facing APIs.

### Existing database details

The database also has indexes for frequently queried project, membership, issue, comment, assignee, label, and history fields.

An existing `set_updated_at()` PostgreSQL trigger function updates `updated_at` on `users`, `projects`, `issues`, and `issue_comments`.

Inspect the real schema if a database inspection connection is available. Otherwise, document any assumptions and generate a safe reconciliation plan.

Do not create duplicate triggers, indexes, tables, or constraints.

- `POST /api/auth/login`
- `GET /api/auth/me`

Requirements:
